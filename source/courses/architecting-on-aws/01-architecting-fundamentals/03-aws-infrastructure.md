# AWS Infrastructure

บทเรียนนี้แนะนำโครงสร้างการจัดวาง (organization) ของ **AWS Global Infrastructure** และวิธีนำไปใช้ในการสร้างแอปพลิเคชันที่มีประสิทธิภาพ

## AWS Global Infrastructure

AWS Global Cloud Infrastructure เป็นแพลตฟอร์มคลาวด์ที่ปลอดภัย ครอบคลุมกว้างขวาง และเชื่อถือได้ ให้บริการมากกว่า 200 บริการเต็มรูปแบบจาก data center ทั่วโลก โครงสร้างพื้นฐานแบ่งออกเป็นระดับต่าง ๆ ดังนี้

### AWS Data Centers
AWS เป็นผู้บุกเบิก cloud computing ตั้งแต่ปี 2006 โดยพัฒนาโครงสร้างพื้นฐานที่รวดเร็วและปลอดภัยอย่างต่อเนื่อง มีการออกแบบและปรับปรุงระบบของ data center เพื่อป้องกันความเสี่ยงทั้งจากภัยธรรมชาติและจากมนุษย์ AWS มี data center ขนาดใหญ่ระดับโลก พร้อมมีการควบคุม ระบบอัตโนมัติ และการตรวจสอบ (audit) จากบุคคลที่สาม เพื่อยืนยันความปลอดภัยและการปฏิบัติตามมาตรฐาน (compliance) ทำให้องค์กรที่มีการกำกับดูแลเข้มงวดที่สุดในโลกไว้วางใจใช้ AWS

### Availability Zone (AZ)
**Availability Zone** คือ data center หนึ่งแห่งขึ้นไปที่มีระบบไฟฟ้า เครือข่าย และการเชื่อมต่อสำรอง (redundant) อยู่ภายใน AWS Region เดียวกัน โดย AZ หลาย ๆ แห่งจะเป็นพื้นที่แยกจากกันภายในภูมิภาคเดียวกัน เมื่อสร้าง instance สามารถเลือก AZ เองหรือให้ AWS เลือกให้ก็ได้ หากกระจาย instance ไปยังหลาย AZ แล้ว instance หนึ่งล่ม ก็สามารถออกแบบให้ instance ใน AZ อื่นรองรับคำขอแทนได้ (ช่วยเพิ่ม **high availability**)

### Region
**AWS Region** แต่ละแห่งประกอบด้วย Availability Zone หลายแห่งที่แยกจากกันทางกายภาพ (isolated) ภายในพื้นที่ทางภูมิศาสตร์เดียวกัน ทำให้ได้ fault tolerance และความเสถียรสูงสุด ผู้ใช้งานสามารถเลือกได้เองว่าจะใช้ Region ใดในบัญชีของตน และสามารถรันแอปพลิเคชัน/workload จาก Region ที่ใกล้ผู้ใช้เพื่อลด latency ได้ โดยไม่ต้องลงทุนล่วงหน้า ไม่ต้องผูกมัดระยะยาว และไม่ต้องกังวลเรื่องการขยายระบบเอง

### AWS Local Zones
**AWS Local Zones** เหมาะกับแอปพลิเคชันที่ต้องการ latency ต่ำระดับหลักหน่วยมิลลิวินาที (single-digit millisecond) เช่น งานสร้างสื่อ/บันเทิง (media and entertainment content creation), เกมแบบผู้เล่นหลายคนแบบเรียลไทม์ (real-time multiplayer gaming) และการฝึก/รัน machine learning โดย Local Zones ช่วยให้ใช้บริการ compute, storage และเชื่อมต่อกับบริการใน AWS Region ได้ พร้อมส่งมอบแอปพลิเคชันที่มี latency ต่ำ

AWS Local Zones ยังเชื่อมต่อกับ parent region ผ่าน Amazon private network ที่มี redundancy และ bandwidth สูง ทำให้แอปพลิเคชันที่รันบน Local Zones เข้าถึงบริการ AWS อื่น ๆ ได้อย่างรวดเร็ว ปลอดภัย และราบรื่น

## AWS Edge Locations
**Edge location** คือจุดที่อยู่ใกล้ผู้ขอใช้บริการ (requester) มากที่สุด กระจายอยู่ตามเมืองใหญ่ทั่วโลก ทำหน้าที่รับคำขอและแคช (cache) สำเนาข้อมูล/เนื้อหาไว้ เพื่อส่งมอบเนื้อหาได้เร็วขึ้น

**ตัวอย่างการใช้งาน (Edge location use case):** ไฟล์วิดีโอที่เก็บใน Amazon S3 ในภูมิภาคอเมริกาใต้ ถูกแคชไปยัง edge location ที่อยู่ใกล้ลูกค้าในเอเชีย เพื่อส่งมอบไฟล์วิดีโอได้เร็วขึ้น — นี่คือตัวอย่างการใช้ edge location ทั่วไป ที่นำเนื้อหาเข้าใกล้ผู้ใช้มากขึ้นเพื่อประสิทธิภาพที่ดีกว่า

## ปัจจัยที่มีผลต่อการเลือก Region (Factors impacting Region selection)

เมื่อจะเลือกใช้ AWS Region ควรพิจารณา 4 ปัจจัยหลัก:

- **Governance** — ข้อกำหนดด้านการกำกับดูแล/กฎระเบียบ (เช่น กฎหมายคุ้มครองข้อมูลในพื้นที่)
- **Latency** — ความหน่วงในการเข้าถึงของผู้ใช้ปลายทาง
- **Service availability** — บริการที่ต้องการมีให้ใช้งานใน Region นั้นหรือไม่
- **Cost** — ต้นทุนค่าใช้บริการ

## สรุป

AWS Infrastructure ประกอบด้วยลำดับชั้นตั้งแต่ data center → Availability Zone → Region รวมถึง Local Zones และ Edge Locations ที่ช่วยขยายขอบเขตการให้บริการให้ใกล้ผู้ใช้มากที่สุด บทเรียนถัดไปจะพูดถึง **Well-Architected Framework** ซึ่งเป็นกรอบแนวทางสำหรับสร้างแอปพลิเคชันคลาวด์อย่างมีประสิทธิภาพบน AWS infrastructure นี้

## Key terms
- Availability Zone (AZ): กลุ่ม data center ที่แยกจากกันทางกายภาพภายใน Region เดียวกัน มีไฟฟ้า/เครือข่ายสำรอง ช่วยเพิ่มความพร้อมใช้งานสูง
- Region: พื้นที่ทางภูมิศาสตร์ที่ประกอบด้วยหลาย Availability Zone
- AWS Local Zones: ส่วนขยายของ AWS Region ที่อยู่ใกล้ผู้ใช้งานมากขึ้น เพื่อรองรับงานที่ต้องการ latency ต่ำมาก
- Edge location: จุดให้บริการแคชเนื้อหาที่กระจายตามเมืองต่าง ๆ ทั่วโลก เพื่อลด latency ในการส่งมอบเนื้อหา
- Fault tolerance: ความสามารถของระบบในการทำงานต่อได้แม้มีบางส่วนล้มเหลว
- High availability: ความพร้อมใช้งานของระบบในระดับสูง ลดโอกาสระบบหยุดทำงาน
- Governance: การกำกับดูแลตามกฎระเบียบ/ข้อบังคับ ซึ่งเป็นหนึ่งในปัจจัยเลือก Region
