# A mechanism for continuous improvement

## A mechanism for continuous improvement (1.3)
สไลด์แสดงวงจร 3 ขั้นตอน (แสดงเป็นไอคอน): **Learn → Measure → Improve**

การทำ framework review ควรมองเป็นขั้นตอนหนึ่งในแผนการปรับปรุงอย่างต่อเนื่อง (continuous improvement plan) ที่เชื่อมโยงกับ workload lifecycle:

- **Learn** — เริ่มจากเรียนรู้กลยุทธ์และ best practices สำหรับการออกแบบสถาปัตยกรรมบน cloud
- **Measure** — วัดผลสถาปัตยกรรมของคุณโดยใช้ framework, AWS Well-Architected lenses และ best practices ขององค์กรผ่าน custom lenses ใน **AWS Well-Architected Tool**
- **Improve** — นำผลลัพธ์จากการวัดผลมาปรับปรุงสถาปัตยกรรม cloud โดยแก้ไขประเด็นความเสี่ยงสูง (high-risk issues) ซึ่งสามารถระบุได้จาก improvement plans, Well-Architected Labs, AWS Partner Network, ทีม AWS Solutions Architecture และอื่น ๆ

กลไก 3 ขั้นตอนนี้ต้องถูกนำไปใช้อย่างสม่ำเสมอกับทุก workload ในองค์กร โดย **workload** หมายถึงกลุ่มของ component ต่าง ๆ ที่รวมกันแล้วส่งมอบคุณค่าทางธุรกิจ (business value)

## Key terms
- Workload: ชุดของ component ที่ทำงานร่วมกันเพื่อส่งมอบคุณค่าทางธุรกิจ
- High-risk issue: ประเด็นความเสี่ยงสูงที่พบจากการ review ซึ่งควรได้รับการแก้ไข
- Improvement plan: แผนการปรับปรุงที่ได้จากผล review
